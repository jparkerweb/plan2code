Your agent and your plan, in one window.

Plan2Code is a short, structured workflow where your AI agent asks, you decide, and the specs land in your repo as plain files. Version 3 adds an optional desktop app that holds the dashboard and your agent side by side.

$ npx --allow-git=all git+https://github.com/jparkerweb/plan2code.git

then, from your project, run plan2code (Claude Code, Devin or Codex), or type /plan2code in your agent ($plan2code in Codex).

Prefer the terminal? See the workflow What is new in v3

Before you start

  • Node.js 18 or newer. Check with node --version. No Node? Get it from nodejs.org (the LTS download), or run winget install OpenJS.NodeJS.LTS on Windows, brew install node on macOS, or use nvm on Linux. Then open a new terminal.
  • Start from your project. Open your terminal in the project you want to work on (cd into it) before you run anything. Plan2Code works on the folder you start it in.
  • Ways in. plan2code (Claude Code, Devin or Codex), or type /plan2code in your agent ($plan2code in Codex).
  • No agent yet? Install Claude Code, Codex or Devin first, or let the plan2code command's setup page walk you through it.

Pathfinder

Plan

The git board

        
Three tabs, Changes, Branches and Sync, and it opens on the one holding your likely next step: commit, pull, push, publish, open a pull request or tidy up branches. That step is one main button. Each tab badges what is waiting on it, a stopped rebase or merge gets one block with every file marked, and nothing is pushed, published or deleted without asking. It never force-pushes.

      

    

  






  

    
What is new in v3

    
Version 3.0.0 adds a desktop app and what runs inside it, plus two utilities. None of it replaces the page or the terminal flow.

    
    
      
  • 
        
    The desktop app
    
        
    
          
    One window: the dashboard as the main surface and your agent in a terminal panel the app owns (Claude Code, Devin, Codex or your own). New Session replaces the agent with a fresh one on a brief the app builds from its own record of the session, so in-progress work carries over. Update skills brings the installed skills level with the app, and the taskbar shows when Plan2Code needs you. Ask, Workspace, Help, Preferences, Git and Notebook open inside the window.

  • 
        
    The Implementation Loop
    
        
    
          
    Builds a whole spec phase by phase, each phase in a fresh agent, and writes a report. It lives in the desktop app and replaces the old plan2code-loop CLI. Set strength per phase runs each phase on the model and effort of a strength you choose: Thrifty, Balanced, Best or Match my session. The loop strip and the report show what each phase ran on.

How a session goes

    
One page, from the first card to the sign-off. Your agent does the work in its terminal (or the app's terminal panel); you do your part here.


    

      
        
        
      
      

        
1

        
Pick a card, answer on the page

        
Pick a step on the dashboard and it starts right there. Questions arrive a few at a time, each option with its trade-off written under it.

      

    


    

      
        
        
      
      

        
2

        
Watch it build

        
Tasks tick off as they land, and the line beside Planny says what is being worked on right now.

      

    


    

      
        
        
      
      

        
3

        
Sign off

        
Read the completion report, then approve the phase or ask for changes. In Implement, you can also have the code reviewed first.

      

    

  






  

    
What the page gives you

    
The same workflow as the terminal, with more room to think. The page is there whether or not you use the desktop app.

    

      
Trade-offs in plain view
Questions arrive a few at a time, each option with its trade-off written under it, so you choose rather than guess.

      
Review before you approve
Review the code first, on the sign-off card, reviews exactly the files the phase changed. You tick which findings get fixed, then approve.

      
The Ask tab
A chat beside the cards for anything you want to know. It is answered at the agent's next check-in and never holds up your answers.

      
Attachments on notes
Paste a screenshot or attach a document to a note on any question, and show instead of describe.

      
A notebook of your own
A private pad for each project folder, in Markdown with pictures. It never goes into your project, and the agent reads a tab only when you start a workflow from it and send it.

      
Workspace folders
Add a shared library or a design folder as read-only context, and point at it by its @name.

      
Session meter
A ring in the top bar turns from green to red as a session grows long, and suggests when a fresh one would serve you better.

      
Runs on your machine
A small program Plan2Code starts for you serves the page on 127.0.0.1. No account, no dependencies, and nothing leaves your computer.

    

    

      
      
      
    

  






  

    
The rules

    
Four rules do most of the work.

    
    
      
  1. Keep each session short.
    Chaining a couple of small skills on the dashboard is fine. Start a fresh console session when the session meter turns red, and always before a big planning or build step. The specs on disk carry everything between sessions.
    2. 
      
  2. No code until the plan hits 90% confidence.
    Step 1 will not finalize below the threshold. Under it, the agent keeps asking and keeps reading your code, and writes every assumption down where you can argue with it.
    3. 
      
  3. Checkboxes are the state, not the chat.
    Progress lives in the spec files. Any agent, any session, resumes cold from them.
    4. 
      
  4. Approve a phase to close it.
    On the sign-off card, or by replying approved in the terminal. Nothing advances on a guess about what you meant.
    5. 
    

    

      
      
When the agent is not running, you lose nothing. The plan, the tasks and the ticks are files in your repo, so a fresh session picks up where the last one stopped.

    

  






  

    

      
Prefer the terminal?

      
The desktop app is optional, and the workflow, the specs and the skills are the same without it. plan2code --classic keeps the terminal flow, and every skill also runs right in the terminal. Each one asks at the start whether you want the page or the terminal; add --web to skip the question and go straight to the page.

      
See every command in the README

    

    
# the terminal flow
plan2code --classic
# or, in your agent
/plan2code
/plan2code-1-plan --web plan a REST API for tasks

  






  

    
Install

    
Run it again any time to update.

    

      
$ npx --allow-git=all git+https://github.com/jparkerweb/plan2code.git

      
    

    
then, from your project, run plan2code (Claude Code, Devin or Codex), or type /plan2code in your agent ($plan2code in Codex).

    
It always opens a menu; no output at all means npm could not reach the repository and hid the reason: git ls-remote https://github.com/jparkerweb/plan2code.git shows why.

    
The installer also offers the desktop app. Answer Y to install it: the file is checked against the release's checksum before it is kept. There are builds for Windows x64, macOS (Apple silicon and Intel) and Linux x64, and the app needs Node.js 18 or newer. Plan2Code works without it.
